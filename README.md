# A股短线雷达

面向个人自选池的 A 股 1-3 个交易日短线仪表盘与**飞书自建应用机器人**推送。策略只在市场、K线、均线、MACD、分时结构、收益风险比和公告门槛同时通过时生成计划；没有买点或卖点就不操作，最长持有到第 3 个可卖交易日。消息发送到配置的 `FEISHU_CHAT_ID`，不再内置个人接收会话。

## 飞书机器人配置与能力

使用飞书开放平台的**企业自建应用 + 机器人能力**，不是只有 Webhook 的群自定义机器人。以应用身份获取 `tenant_access_token`，无需用户登录或 `im:message.send_as_user` 授权。

| 配置 | 用途 | 必填 |
|---|---|---|
| `FEISHU_APP_ID` | 自建应用 App ID | 推送及 Bot 服务必填 |
| `FEISHU_APP_SECRET` | 同一应用的 App Secret | 推送及 Bot 服务必填 |
| `FEISHU_CHAT_ID` | 机器人所在群聊或单聊会话的 `oc_...` 标识 | 全部机器人推送必填 |
| `DEEPSEEK_API_KEY` | DeepSeek 模型调用凭据，和飞书凭据独立 | 使用大模型必须提供 |

模型 API Key 用于**信号审核和晚间复盘**，不只是润色文字。未配置、调用失败或返回无效结构时，暂停新增买入及非硬性退出，明确显示AI不可用；止损、目标位、最长持有期等硬性退出仍按规则执行，T+1优先。行情查询、成交登记和盈亏计算仍可运行，晚间不修改参数，不回退到“亏损就收紧”的旧调参方式。

### 开放平台配置步骤

1. 在飞书开放平台创建企业自建应用，启用「机器人」应用能力。
2. 在「权限管理」为**应用身份**开通「以应用的身份发消息」`im:message:send_as_bot`（已有 `im:message` 权限也可覆盖发送能力）。
3. 如需查询/登记交互，在「事件与回调」选择长连接订阅方式，添加接收消息事件 `im.message.receive_v1` 和卡片回调 `card.action.trigger`。群内命令开通「接收群聊中 @ 机器人消息」`im:message.group_at_msg:readonly`；单聊命令开通「读取用户发给机器人的单聊消息」`im:message.p2p_msg:readonly`。不需要读取群内全部消息、通讯录、云盘或审批权限。
4. 创建版本并发布，完成企业管理员审批；应用可用范围应包含实际使用者。权限变更也需要重新发布生效。
5. 把机器人加入目标群，或与该机器人建立单聊，从该会话的消息事件 `chat_id` 获取 `oc_...` 标识，配置为 `FEISHU_CHAT_ID`。不能用用户 `open_id`、邮箱或 `user_id` 代替。群内输入 `@机器人 帮助` 或单聊输入 `帮助` 验证交互。
6. 启动长连接 Bot 后，确认事件订阅和卡片回调均已启用；只开消息事件不能接收卡片提交。仅单向推送不需要启动 Bot 或配置事件订阅。

| 机器人能力 | 入口/行为 | 运行要求 |
|---|---|---|
| 盘中推送 | 每5分钟扫描，信号变化才发卡片，含可选 AI 解读与K线 | 外部定时调用或扫描 daemon |
| 收盘推送 | 市场概况、实际持仓收盘盈亏、可选 AI 解读 | `server.py --scheduled-push close-summary` |
| 查询行情、持仓、帮助 | `代码或已登记名称`、`持仓`、`帮助` | `bot_ws.py` 长连接在线 |
| 实际成交登记 | `300398 已买入/已卖出` 或卡片按钮，填写实际价格和股数 | 消息事件和卡片回调均启用 |
| 日/周复盘推送 | 实际操作、期间盈亏、已实现盈亏、浮盈亏与规则更新 | 外部任务在20:00调用，周五额外周复盘 |

所有推送和交互共用 `FEISHU_CHAT_ID`，Bot 仅处理该会话的消息/回调。它不向券商下单、不自动读取券商账户、不自动同步另一台机器的账本。应用机器人 API 发送成功代表服务端已接收消息，不代表用户已读或已成交。

### 运行环境

```bash
cp .env.example .env
# 在本地编辑 .env 填入配置，不要把密钥发到聊天或提交仓库
chmod 600 .env
set -a
source .env
set +a
# 仅交互 Bot 需要第三方 SDK
python3 -m pip install lark-oapi
python3 -B bot_ws.py
```

`.env` 只由 `startup.sh` 自动加载；直接运行 Python 或 cron/豆包任务时，应由任务环境注入变量，或先如上加载 `.env`。`bash startup.sh` 使用脚本所在目录，不依赖豆包机器的固定路径；它启动 Bot 并在当前交易时段启动扫描，但不是全天日程调度器，不会自动安排收盘和20:00复盘。生产环境应使用服务管理器与定时任务保持 Bot 在线、调度各命令，并共享持久化私有 `data/`。

打开 `http://127.0.0.1:8765`。页面每 60 秒刷新，飞书推送配置保存在本机 `data/` 目录，该目录不会提交到 Git。

## 代码结构

| `actual_trades.py` | 实际成交校验、T+1、幂等登记和账本更新 |
| `ai_strategy.py` / `signal_review.py` | 结构化AI信号审核 / 信号快照与后续交易日表现评估 |

## 每日推送流程

正式通道分为盘中状态变化与收盘总结：

- LightClaw 在 `09:35–11:30`、`13:00–15:00` 每 5 分钟运行 `python3 -B server.py --lightclaw-scan-prepare`。只有逐标的买卖信号状态变化时才返回待发送消息；持续同一信号、午休、闭市、休市或行情不足均不推送。
- 当前飞书会话确认消息送达后，使用返回的永久 token 执行 `python3 -B server.py --lightclaw-commit TOKEN`；送达失败不得 commit。
- GitHub Actions 仅在工作日北京时间 `15:30` 向飞书私信推送收盘总结，行情截点固定为实际收盘的 `15:00`。`10:00`、`10:30`、`14:30` 不再定时运行，也不是正式盘中通道。

盘中扫描不读取或调用推送通道；全局 pending 未提交时不会生成或覆盖另一批消息。行情日期不是当天、整体行情未达到本轮截点或持仓行情缺失时采用安全降级，不建立新仓，也不把不可判断的旧信号误清除。

### 盘中包装脚本与失败恢复

`python3 -B scan_and_push.py` 执行一次扫描、飞书卡片发送和策略提交；无新信号正常退出。`--daemon` 在交易时段每 5 分钟扫描，到收盘退出。运行环境需要提供 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_CHAT_ID`，应用必须有权向配置的目标会话发消息。daemon 的假定持仓止损预警与实际账本独立，发送后只在交易锁内合并去重标记，不覆盖并发成交登记。

包装脚本通过 `--lightclaw-scan-prepare --resume-pending` 优先恢复原有盘中批次（即使已跨扫描时点或闭市），使用原始决策时间、结构化 `actions` 和永久 token，不从正文猜股票代码或买卖方向。送达后先保存飞书 `message_id`，再提交；提交失败的下次执行只重试提交，不再发送。发送重试使用同一批次的稳定 UUID，利用飞书接口的有限去重窗口降低重复发送风险；网络结果不确定或超出去重窗口时仍需核对消息，不能保证无限期的恰好一次送达。不要丢弃 `data/trading-state.json`，也不要手工覆盖 pending；原有不带 `--resume-pending` 的调用仍保留跨时点冲突保护。

`send_bot.py <chat_id> <card_json或@文件路径> [--uuid 标识]` 成功时输出单个 JSON 对象，失败时非零退出。`server.py --print-report close-summary` 只生成卡片、不发送或提交；休市、陈旧或未达到阶段截点的行情输出 `status: no_report`。

如使用已有 GitHub Actions 收盘工作流，在仓库中配置（其他环境直接配置同名环境变量）：

1. 打开 `Settings` -> `Secrets and variables` -> `Actions`。
2. 按上文配置机器人权限与可用范围，然后新建 Repository secrets：
   - `FEISHU_APP_ID`：应用 App ID
   - `FEISHU_APP_SECRET`：应用 App Secret
   - `FEISHU_CHAT_ID`：目标会话 `oc_...`
   - `DEEPSEEK_API_KEY`：启用大模型解读时必填
3. 邮箱 `FEISHU_RECEIVE_ID` 和 `FEISHU_WEBHOOK` / `FEISHU_SIGNING_SECRET` 只保留旧入口兼容；配置 `FEISHU_CHAT_ID` 后收盘优先走应用机器人卡片，不回退邮箱或 Webhook。盘中、复盘和交互仅支持配置的机器人会话，不使用旧通道。
4. 如需在收盘总结中跟踪人工登记的持仓，另建 Repository secret `ASTOCK_MANUAL_HOLDINGS`，值为 JSON 数组，例如 `[{"code":"000001","shares":100,"buy_price":10.00,"buy_date":"2026-01-05"}]`。该持仓只报告收盘价和浮动盈亏，不进入策略自动买卖决策。
5. 打开 `Actions` -> `Daily A-share push`；定时任务只运行收盘总结，`Run workflow` 仍可手工选择兼容阶段。

应用凭据和 Webhook 不得写入代码、工作流文件、提交记录或聊天消息；已经泄露的凭据应在飞书中重置。

## AI决策与解读

### AI参与选股与信号判定

先运行确定性规则，再把通过市场、技术、分时、公告和资金门槛的买入候选交给AI**排序、确认或否决**，最后按原有仓位预算和整手规则计算数量。AI不能添加未通过规则的股票、修改报价或股数，也不能绕过市场红灯、仓位上限和禁止加仓约束。

持仓的日线转空、盘中走弱等非硬性卖点需要AI确认。止损失效位、目标位、最长持有期及已有市场红灯退出条件不受AI否决，任何卖出仍先遵守T+1和行情核验。当前策略卖出仍针对假定持仓，真实持仓独立记账；AI不连接券商，不把策略信号当成实际成交。

审核只接受严格JSON，校验输入标的完整性、唯一性、布尔裁决和理由；遗漏、重复、越权或不可解析输出均视为失败。冻结 pending 保存生成时的审核结果、模型标识与输入哈希，恢复/提交不重新调用模型。盘中卡片展示买入审核理由；飞书查股显示最近扫描的审核快照和时间，不假装重新生成实时信号。无规则候选且无非硬性卖点时不调用决策模型。

收盘的AI盘面解读仍保留，但收盘报告本身不产生交易操作。模型调用会将所需技术指标、公开公告标题及复盘证据发送至配置的 DeepSeek 服务，并产生API费用；凭据仅从 `DEEPSEEK_API_KEY` 读取，不写入报告或账本。

## 假定持仓

GitHub Actions 使用 `data/trading-state.json` 记录假定成交，不把个人持仓提交到公开仓库。文件通过 Actions cache 在任务间恢复，内容包括买入日、参考买价、数量、失效位、目标位、卖出参考价和收益率。

收益率口径为 `(卖出参考价 / 假定买入价 - 1) * 100%`，未计佣金、印花税和滑点，也不代表券商账户的真实成交收益。由于机器人无法确认实际委托是否成交，建议以券商成交记录为最终准绳。

## 实际成交登记

`bot_ws.py` 需要运行环境安装 `lark-oapi`，并在飞书应用中启用消息接收事件和卡片回调长连接。定时扫描进程本身不接收卡片回调，Bot 必须另行保持在线；本次代码修复不部署或启用任何定时任务和服务。

在配置的目标会话里使用 `@bot 000001 已买入` / `已卖出`，或点击新信号卡片的「登记实际买入/卖出」，填写**实际成交价格与正整数股数**后提交。此操作不向券商下单。缺少价格/数量、非正数、非有限价格、当日 T+1 卖出和超额卖出均拒绝登记，不会再创建零股数或零目标价持仓。同一表单/信号重复回调不会重复记账；重复请求中的成交数据不一致会明确报错。信号卡片仅支持当日登记，过期或旧版无标识卡片请改用手工登记。单个信号只登记一次成交，不支持自动加仓或同一信号多笔成交；手工登记日期采用提交当天。

真实成交保存于同一私有状态文件的 `actual_holdings`、`actual_history`、`actual_trade_receipts` 字段；所有更新使用跨进程交易锁，不修改策略的 `holdings`、`history` 或冻结 pending。`@bot 持仓` 查看实际账本，收盘报告汇总实际持仓和 `ASTOCK_MANUAL_HOLDINGS`（同代码以实际账本为准），只报告价格与盈亏，不据此生成策略委托。旧版持仓不自动迁入实际账本，避免把假定成交当成真实成交；已有历史仓位仍可使用 `ASTOCK_MANUAL_HOLDINGS` 监控。

实际账本中的未平仓股票自动并入基础自选池并去重，参与行情获取、仪表盘、规则筛选及收盘报告；仍须通过原有市场、技术和公告门槛才能成为策略候选，不会因实际持有而直接产生策略买入。全部卖出后，非基础自选股在下一次分析时退出动态池；基础自选股保留。池组成改变会使仪表盘行情缓存失效，正式报告的 `stock_pool` 及哈希记录实际使用的动态池。已冻结的待发送批次保持原样，恢复或提交不会重算为新池。

## 晚间实际操作复盘

供豆包定时任务调用，时区均为 **Asia/Shanghai**，不需要启动常驻进程：

- 每天 20:00：`python3 -B trade_review.py --period daily --apply-rules --send`
- 每周五 20:00 **额外执行**：`python3 -B trade_review.py --period weekly --apply-rules --send`

周五两条命令都运行，分别发送日复盘和本周一至当天的周复盘。去掉 `--send --apply-rules` 只输出 JSON 和规则变更预览，不发送或修改规则；可用 `--as-of 2026-10-28` 补查指定截止日期（不得是未来日期）。`--apply-rules` 只允许北京时间当天20:00后执行，不允许历史报告改写规则。本功能仅提供入口，未创建、启用或修改豆包/GitHub/Automations 定时任务。执行环境需有最新代码、同一份私有 `data/trading-state.json` 和飞书应用凭据；只同步 Git 代码不会同步实际账本与规则。

报告列出本期买卖、期末持仓和三种独立口径：**本期盈亏**按期初/期末收盘价计价，期内买入/卖出使用实际成交价；**本期已实现盈亏**按卖出价减买入成本；**期末持仓浮盈亏**按收盘价减买入成本。三者不能直接相加。金额未扣佣金、印花税等费用，不冒充券商净收益；不混入策略假定交易。行情缺失或未达到收盘时，不用旧行情冒充当日收盘价，无法计算的金额明确留空。非交易日可能无法获得当日收盘价，仍报告已登记操作并提示行情缺失。

### 自动修改规则

扫描和正式决策保存规则候选的AI确认/否决快照及硬性退出信号；即使AI否决后没有推送也保留记录。以信号价为基准，跟踪之后第1、2、3个**经指数日线确认的交易日**的收盘表现，买入后上涨、卖出后下跌定义为方向正确。休市不算天数，缺行情与未到期不算失败；批准和否决样本分别统计，实际成交盈亏与方向指标分开展示。每日报告也纳入今天刚满3个交易日的旧信号，避免每天只看到未成熟的当天信号。

同股同日同方向同裁决只取首次快照，避免5分钟扫描重复充当独立样本。通过信号表单登记的成交可关联；没有关联记录不等于用户没有操作。被否决信号的表现只是反事实参考，不是账户收益或漏选的因果证明。只评估新功能上线后保存的信号；历史行情不足时明确标注，不能补造此前的AI决策。晚间任务通过完整收盘分时保存信号日真实收盘价，用于校准后续前复权日线，避免除权造成虚假亏损；缺少基准或日线降级为未复权数据时不计算该信号收益。只读复盘不保存基准，正常夜间任务应使用 `--apply-rules --send`。

AI读取本期信号表现、实际操作与盈亏，直接决定是否修改已授权的 **最低入场盈亏比** 与 **最长可卖交易日数**：

- 至少10个成熟独立的股票/日期/方向样本，且相关行情完整，才允许修改；样本不足仍生成AI分析，但保持规则。
- 最低盈亏比限制在 `2–3R`，单次最多变动 `0.2R`；最长持有期限制在 `1–3` 个可卖交易日，单次最多变动1日。
- 模型失败、输出越界或证据不足时不改规则，不回退到旧的实际盈亏机械调参。

## 交易口径

- 盘中决定使用不晚于本轮实际扫描时刻、且已达到该 cutoff 的当日行情；09:30 数据不足不产信号。
- 买入后遵守 A 股 T+1；下一交易日是第 1 个可卖交易日。
- 第 1-2 个可卖交易日没有卖点可以继续持有；第 3 个可卖交易日盘中触发时间退出。
- 卖点包括交易逻辑失效、达到目标位、日线转空、盘中分时走弱，以及第 3 个可卖交易日的时间退出。
- 红灯市场、关键数据缺失、公告未核验或个股硬门槛失败时不建立新仓。
- 自动筛选仅供研究参考，不构成个性化投资建议。
