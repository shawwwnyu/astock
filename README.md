# A股短线雷达

面向个人自选池的 A 股 1-3 个交易日短线仪表盘与企业微信推送。策略只在市场、K线、均线、MACD、分时结构、收益风险比和公告门槛同时通过时生成计划；没有买点或卖点就不操作，最长持有到第 3 个可卖交易日。

## 本地运行

```bash
python3 -B server.py --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765`。页面每 60 秒刷新，企业微信配置保存在本机 `data/` 目录，该目录不会提交到 Git。

## 每日推送流程

工作流 `.github/workflows/daily-push.yml` 在工作日按北京时间执行：

- `10:00`：早盘市场概况，不产生交易指令。
- `10:30`：复核已有假定持仓；出现卖点则给出卖出指令和收益率，否则继续持有。同时在本金池可用时检查早盘买点。
- `14:30`：检查尾盘买点；已有持仓时不重复占用 50,000 元本金池。
- `15:30`：推送收盘总结，行情截点固定为实际收盘的 `15:00`。

GitHub cron 可能排队延迟，因此程序按触发的阶段固定截取 `10:00`、`10:30`、`14:30` 或 `15:00` 的行情，不按任务实际启动时间猜测阶段。行情日期不是当天时会按休市或数据过期跳过。

企业微信群机器人 Webhook 是单向通道，程序无法接收用户回复。规则是：消息发送成功后，默认用户执行消息中明确的买入或卖出指令；“持有”“观察”“空仓”和“没有买卖点”不会产生交易。发送失败不会修改假定持仓。

在仓库中配置：

1. 打开 `Settings` -> `Secrets and variables` -> `Actions`。
2. 新建 Repository secret，名称为 `WECOM_WEBHOOK`。
3. 值填写企业微信“消息推送”生成的完整官方 Webhook。
4. 打开 `Actions` -> `Daily A-share push`，使用 `Run workflow` 时可选择四个推送阶段。

Webhook 不得写入代码、工作流文件、提交记录或聊天消息。已经泄露的 Webhook 应先在企业微信中删除并重新创建。

## 假定持仓

GitHub Actions 使用 `data/trading-state.json` 记录假定成交，不把个人持仓提交到公开仓库。文件通过 Actions cache 在任务间恢复，内容包括买入日、参考买价、数量、失效位、目标位、卖出参考价和收益率。

收益率口径为 `(卖出参考价 / 假定买入价 - 1) * 100%`，未计佣金、印花税和滑点，也不代表券商账户的真实成交收益。由于机器人无法确认实际委托是否成交，建议以券商成交记录为最终准绳。

## 交易口径

- 10:30 和 14:30 的买入决定分别使用不晚于对应时点的行情。
- 买入后遵守 A 股 T+1；下一交易日是第 1 个可卖交易日。
- 第 1-2 个可卖交易日没有卖点可以继续持有；第 3 个可卖交易日 10:30 强制给出退出指令。
- 卖点包括交易逻辑失效、达到目标位、日线转空、早盘分时走弱，以及第 3 个可卖交易日的时间退出。
- 红灯市场、关键数据缺失、公告未核验或个股硬门槛失败时不建立新仓。
- 自动筛选仅供研究参考，不构成个性化投资建议。
